# Outcome Recipes

These recipes define order and proof, not fixed tool schemas. Discover every dynamic tool before use and let one CLI, Clippy workflow, MCP call, or Python recipe own each mutation.

## Review cut from a long video

1. Import/upload/register the intended source and wait for readiness.
2. Read audio health; retrieve or create a transcript.
3. Load creator preferences only when they affect the request.
4. Inspect transcript context and select a complete hook-to-payoff range.
5. Create candidate clips, then inspect their exact source bounds.
6. Create/select a project and sequence; assemble A-roll and re-read the timeline.
7. Apply destination framing, captions, and graphics.
8. Add only justified B-Roll or Alter work after plan, approval, and generation QA.
9. Analyze and polish audio.
10. Run delivery QA, render/export the current state, and inspect the artifact.

## Creator-style social package

1. Read the creator profile and learned preferences.
2. Separate explicit user direction from inferred preferences.
3. Build one shared visual direction for clip, captions, thumbnail, and B-Roll.
4. Prepare a thumbnail prompt and B-Roll plan before any generation.
5. Present concepts and a live capped estimate; generate approved assets only.
6. Apply assets to the intended clip-local ranges and inspect identity/crop/continuity.
7. Run delivery QA before social copy or scheduling.
8. Refresh exact social accounts and obtain separate publish/schedule approval.

## B-Roll package

1. Read the target clip/transcript and identify the spoken moment needing proof, clarification, pacing, or emotional support.
2. Read the creator profile when brand context matters.
3. Plan a small set of concepts; label purpose and clip-local placement for each.
4. Choose single-image or compatible start/end-frame mode.
5. Use GPT Image 2 still intent followed by an H3 Max motion-only prompt.
6. Preflight and confirm the selected concept and cap.
7. Wait/resume the generation job; inspect sampled frames.
8. Apply the result to the exact clip-local range and re-read layers.
9. Confirm source audio remains authoritative and run timeline/delivery QA.

## Selected-section Alter

1. Read the current clip and normalize the selected clip-local range.
2. Analyze whether the request is one bounded visual delta and supported by the current tool.
3. Plan first; inspect preservation invariants and estimate.
4. Write a Gemini Omni Flash instruction ending “Keep everything else the same.”
5. Confirm the exact range, operation, and cap; generate once.
6. Wait/resume the same job and compare source/output at matching timestamps.
7. Apply only after QA passes; re-read the resulting layer and preserve source audio.
8. Revert rather than stacking compensating edits if the selected result is wrong.

## Voiceover package

1. Read current audio and target duration.
2. Finalize literal script and separate performance direction.
3. Plan voiceover; verify voice/language and live estimate.
4. Confirm generation and cap.
5. Inspect spoken words, pronunciation, pacing, and duration.
6. Apply as an explicit audio layer, then set placement, volume, fades, ducking, and source-audio behavior.
7. Listen to the final mix and run delivery QA.

## Music-bed package

1. Analyze existing dialogue, source audio, and edit energy.
2. Build an instrumental production brief unless vocals were explicit.
3. Keep provider style/lyrics separate from placement, looping, fades, level, and ducking.
4. Plan, preflight, confirm, and generate under the approved cap.
5. Inspect musical form, unrequested vocals, loop seam, and duration.
6. Apply at restrained level, duck under speech, and listen to the final mix.

## Blueprint-to-edit

1. Confirm the reference blueprint and target sources are authorized and inspectable.
2. Analyze structure, rhythm, graphics, effects, crop, audio, and platform intent without copying protected assets or identity.
3. Convert the analysis into an execution plan with asset mappings and explicit unsupported items.
4. Resolve target assets and audit rollout readiness.
5. Create durable job state; execute one pass at a time and checkpoint after each mutation.
6. Apply text/effect primitives only from approved target content.
7. Run blueprint comparison QA and normal delivery QA on the current result.

## Publish-ready handoff

1. Confirm the selected clip and current exact export.
2. Run delivery QA and resolve/waive every blocker.
3. Create/inspect the thumbnail package if required.
4. Read live social accounts and pin exact account IDs.
5. Draft platform-specific copy without changing facts or quotes.
6. Obtain approval for exact artifact, destination account, copy, timing, and cap.
7. Publish/schedule once; wait for per-platform result and return URLs/errors.

For enterprise, a ready delivery is not client-selected authority. Follow `enterprise-exactness.md` and wait for the client-controlled selected state.
